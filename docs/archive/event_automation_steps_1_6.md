# 이벤트 자동화 프로젝트 1~6단계 정리

## 1단계. 이벤트 브리프 생성
이 단계는 이벤트의 출발점을 정리하는 단계다.  
관리자가 브랜드와 이벤트 기본 정보를 입력하면, 시스템이 이후 단계에서 공통으로 사용할 기준 데이터를 만든다.

### 입력값
- 브랜드명
- 이벤트명
- 목적
- 타깃
- 채널
- 일정
- 오퍼/혜택
- 참고 레퍼런스
- 금지어 또는 필수 포함 문구

### 주요 처리
- 입력값 정규화
- 브랜드 가이드 불러오기
- 이벤트 목적 해석
- 핵심 메시지 후보 정리
- 이후 단계에서 사용할 공통 구조 생성

### 출력값
- 핵심 메시지
- 이벤트 요약
- 톤앤매너 방향
- 콘텐츠 제작 기준
- 공통 브리프 JSON 또는 Markdown

### 왜 필요한가
이 단계가 있어야 이후 카피, 이미지, 레이아웃이 같은 방향으로 움직인다.  
브리프 없이 바로 제작으로 들어가면 채널별 결과물이 서로 어긋나기 쉽다.

---

## 2단계. 콘텐츠 기획 분기
브리프를 바탕으로 어떤 콘텐츠를 어떤 채널에 어떤 형식으로 만들지 나누는 단계다.  
핵심은 하나의 이벤트를 여러 매체에 맞게 분기하는 것이다.

### 주요 처리
- 채널별 목적 구분
- 콘텐츠 형식 결정
- 우선순위 산출물 선정
- 각 채널에 필요한 비주얼 타입 정리

### 예시 산출물
- 인스타 카드뉴스 5장
- 인스타 피드형 1종
- 스레드/트위터용 짧은 이미지 2종
- 네이버 블로그 썸네일 1종
- 브런치 커버 1종
- 커뮤니티 공지 이미지 1종

### 출력값
- 채널별 콘텐츠 플랜
- 산출물 목록
- 콘텐츠 타입별 목적
- 이미지 필요 유형 정리

### 왜 필요한가
같은 이벤트라도 채널마다 필요한 구조가 다르다.  
이 단계가 없으면 같은 이미지와 같은 문구를 여러 채널에 억지로 복제하게 된다.

---

## 3단계. 이미지 후보 생성
이 단계에서는 콘텐츠 타입별로 이미지 생성용 프롬프트를 만들고, Midjourney 같은 툴로 시각 후보를 생산한다.  
핵심은 완성본을 바로 만드는 것이 아니라 후보군을 만드는 것이다.

### 주요 처리
- 콘텐츠 타입별 프롬프트 생성
- 브랜드 톤 반영
- 텍스트가 들어갈 여백 고려
- 표지용/상세용/배너용 등 목적별로 생성 분기
- 후보 이미지 저장 및 분류

### 예시 생성 범위
- 메인 키비주얼 후보 3~4개
- 카드뉴스 표지 후보 3개
- 상세 슬라이드용 보조 이미지 2~3개
- 블로그 썸네일용 후보 2개

### 출력값
- 프롬프트 세트
- 생성된 이미지 후보
- 이미지별 메타데이터
  - 어떤 채널용인지
  - 어떤 콘텐츠 타입인지
  - 표지용인지 상세용인지
  - 어떤 카피와 연결되는지

### 왜 필요한가
이미지 생성은 한 번에 정답이 나오기 어렵다.  
그래서 후보를 만들고, 그중에서 골라 다음 단계로 넘기는 구조가 가장 안정적이다.

---

## 4단계. 관리자 선택
이 단계는 자동 생성된 후보 중에서 실제로 사용할 이미지를 사람이 고르는 단계다.  
전체 파이프라인에서 가장 중요한 품질 제어 지점이다.

### 관리자가 하는 일
- 후보 이미지 확인
- 채택 / 제외 / 재생성 선택
- 채널 용도 변경 가능
- 텍스트 삽입 가능 여부 판단
- 브랜드 적합성 확인

### 선택 기준 예시
- 브랜드 톤에 맞는가
- 이벤트 목적과 맞는가
- 텍스트를 올릴 여백이 있는가
- 카드뉴스 표지로 적합한가
- 다른 채널로도 재활용 가능한가

### 출력값
- 선택된 최종 후보 이미지
- 재생성 요청 목록
- 폐기 목록
- 후속 제작용 확정 에셋

### 왜 필요한가
이 단계 없이 전부 자동으로 연결하면 결과물 수는 많아져도 품질이 흔들린다.  
반자동 구조에서 이 선택 단계가 들어가야 실제 운영 퀄리티가 올라간다.

---

## 5단계. 피그마 조립
선택된 이미지를 바탕으로 실제 채널별 시안을 만드는 단계다.  
여기서 비로소 카드뉴스, 배너, 썸네일 같은 결과물이 만들어진다.

### 주요 처리
- 선택 이미지 불러오기
- 템플릿 매핑
- 카피 삽입
- 슬라이드별 정보 분배
- 채널별 비율 조정
- 카드뉴스 장수별 구성 적용

### 예시 적용
- 카드뉴스 1장: 후킹
- 2장: 문제 제시
- 3장: 혜택 설명
- 4장: 참여 방법
- 5장: CTA

### 출력값
- 인스타 카드뉴스 시안
- 인스타 피드 이미지
- 스레드/트위터용 이미지
- 블로그 썸네일
- 브런치 커버
- 커뮤니티 공지 이미지

### 왜 필요한가
좋은 생성 이미지만으로는 실무 결과물이 완성되지 않는다.  
실제 운영에서는 텍스트 구조, 규격, 채널별 레이아웃이 같이 맞아야 한다.

---

## 6단계. QA 및 패키징
최종 산출물을 검수하고, 실제 운영에 바로 쓸 수 있도록 정리하는 단계다.  
마지막 정리 단계이며, 실무 적용성과 연결된다.

### 주요 처리
- 오탈자 검사
- 금지어 검사
- 브랜드 톤 점검
- 채널별 사이즈 확인
- 파일명 규칙 정리
- 폴더 구조 정리
- 버전 저장

### 체크 항목 예시
- CTA 누락 여부
- 문구 길이 과다 여부
- 채널 규격 불일치 여부
- 잘못된 브랜드 표현 존재 여부
- 카드뉴스 장 순서 오류 여부

### 출력값
- 최종 이미지 패키지
- 채널별 카피 파일
- QA 리포트
- 다운로드용 폴더
- 재수정 필요 항목 목록

### 왜 필요한가
이 단계가 있어야 결과물이 단순 시안이 아니라 실제 배포 가능한 운영 자산이 된다.  
또 이후 비슷한 이벤트를 반복 제작할 때도 자산처럼 재사용할 수 있다.

---

## 전체 흐름 한 줄 요약
1. 이벤트 브리프 생성  
2. 콘텐츠 기획 분기  
3. 이미지 후보 생성  
4. 관리자 선택  
5. 피그마 조립  
6. QA 및 패키징

즉, 한 이벤트를 입력하면 바로 완성본을 한 번에 만드는 구조가 아니라,  
단계를 나눠 품질을 통제하면서 최종적으로 여러 채널용 콘텐츠 세트로 확장하는 구조다.
